# Среда Каспия: погодные слои на карте и путь к early-warning модели

Ветка: `feat/environment` (worktree, PR в main). Задача от кофаундера: парсить погодные условия и температуру воды, наносить на карту, дальше — предикшн перемещений групп.

Принцип тот же, что во всём продукте: **ни одного числа из воздуха**. Каждый слой на карте обязан отвечать на вопрос «откуда взято» источником и временем измерения; всё, что является гипотезой, помечается как гипотеза.

## 1. Источники — что уже проверено живыми запросами (2026-08-10)

| Фактор | Источник | Статус | Проба |
|---|---|---|---|
| Ветер (скорость/направление), t° воздуха | Open-Meteo Forecast API | ✅ работает | точка 44.8, 50.3 — почасовые значения |
| То же исторически (для дат прошлых съёмок) | Open-Meteo Archive API | ✅ работает | 2026-08-07/08 отдаёт |
| Волны (высота) | Open-Meteo Marine API | ✅ работает | 0.16 м реальные, не null |
| Температура воды (SST) | Open-Meteo Marine | ❌ **null по всему Каспию** — глобальная модель маскирует внутреннее море | все 24 ч null |
| Температура воды (SST) | **NOAA OISST v2.1 через ERDDAP** (coastwatch.pfeg.noaa.gov) | ✅ работает | 44.875, 50.375 → 26.51 °C (20.07) |
| Течения | Open-Meteo Marine | ❌ null по Каспию | все null |
| Течения | CMEMS/HYCOM глобальные | ❌ Каспий обычно исключён | не подтверждён ни один источник |
| Лёд | поле `ice` в том же OISST-датасете; OSI-SAF/NSIDC | ⏳ проверка зимой (сейчас август — льда нет физически) | — |
| Кормовая база (рыба) | — | ❌ источника данных нет | — |

Ограничения OISST, которые честно показываем в UI: сетка 0.25° (~20 км), суточное разрешение, лаг публикации от дней до ~2 недель. Это **не** «температура сейчас», это «поле температуры на дату N».

## 2. Архитектура (Phase 1 — backend)

- `service/env.py`: клиенты Open-Meteo (forecast/archive/marine) и ERDDAP OISST; всё через кэш.
- Таблица `env_sample` (аддитивно в schema.sql + `_widen`): `time, lat, lng, source, wind_ms, wind_dir, gust_ms, air_t, wave_m, sst, ice_pct NULL`. Уникальность по (source, time, lat, lng).
- **Backfill на даты визитов**: для каждой существующей съёмки тянем условия на её `captured_at`/дату в её точке (Archive + OISST) — исторические данные появляются сразу, без ожидания.
- Периодический сбор: воркер раз в 3 часа снимает условия по центрам активных участков (+ сетка 0.25° по bbox Каспия для SST) — так копится ряд, без которого никакая модель невозможна.
- Эндпоинты (аддитивные): `GET /v1/env/at?lat&lng&time` (для карточки визита), `GET /v1/env/grid?time` (слой карты: массив точек сетки с ветром/SST).
- Ключей не требуется ни одному источнику; лимиты щадящие, кэш обязателен.

## 3. Карта и карточки (Phase 2 — frontend)

- Тумблер слоя **«Среда»** рядом со «Спутник/Треки/Лежбища»: стрелки ветра по сетке (направление+длина=скорость), SST точками сетки с цветовой шкалой. **Не интерполируем в гладкий градиент** — сетка 0.25° показывается как сетка; красивая заливка поверх 15 реальных точек была бы враньём.
- Карточка визита/участка: блок «условия на момент съёмки»: ветер, волна, t° воздуха, t° воды (+ источник и лаг). Уходит и в PDF-акт.
- Сезонная разметка по биологии (кофаундер): зима=лёд/размножение, весна=линька, лето=кормовые, осень=подготовка. Тег сезона на съёмке, фильтр в аналитике. Сезон — модификатор всех остальных факторов, в одну кучу данные не мешаем.

## 4. Предикшн — честная лестница (Phase 3)

Прямо: **early-warning модель сегодня необучаема** — у нас дни наблюдений, а нужны многолетние треки. Поэтому:

1. **Сейчас**: копим ряды (п.2, воркер) и связку «условия ↔ визиты» — без этого никакой математики не будет никогда.
2. **Монитор условий** (правила-гипотезы, явно помеченные): «ветер >12 м/с держится 6+ ч у участка X — по гипотезе возможен уход группы в спокойный район». Показ как *гипотеза кофаундера, не прогноз*; вероятностей не рисуем.
3. **Когда появятся спутниковые треки** (или годы наших наблюдений): корреляционный фреймворк с лагами 6/12/24/48 ч — какие изменения условий статистически предшествуют перемещению. Приоритет гипотез (кофаундера): лёд → корм → SST-градиент+течения → ветер+волны → t° воздуха; сезон — везде модификатором. Смотрим градиент SST (движение границы тёплой/холодной воды), не абсолют.

## 5. Нерешённое (честно)

- **Течения**: источника для Каспия не найдено (глобальные модели его исключают). Ищем региональные (КазГидроМет, региональные модели); до находки — слоя нет и гипотеза «движение по течению» не проверяема.
- **Лёд**: проверка источников в ноябре (поле `ice` OISST + OSI-SAF); до зимы слой не нужен физически.
- **Кормовая база**: данных нет; фиксируем как верхнюю гипотезу без слоя.
